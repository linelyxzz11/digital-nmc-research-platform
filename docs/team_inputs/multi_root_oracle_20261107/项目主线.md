# 项目主线：

### 第一层：主性能比较

这是回答“我们的 NMC 是否比集中计算更好”的核心实验。

固定：

- 相同 GEMV；
- 相同 INT8/INT32 精度；
- 相同总 MAC 数；
- 相同权重驻留条件；
- 相同输入和输出传输口径；
- 相同物理资源预算；
- 明确统计 kernel-only 和 end-to-end 两种时间。

比较：

| 方法                             | 作用            |
| -------------------------------- | --------------- |
| centralized/single-core baseline | 集中式计算参考  |
| single-Tile sequential NMC       | 无网络 NMC 参考 |
| ROW NMC                          | 广播输入        |
| K NMC + central reduction        | 部分和归约      |
| 2D NMC                           | 综合通信模式    |
| proposed mapper                  | 最终方法        |

这里的 baseline 不能只用 NumPy：

- NumPy 是数值 Golden，不是硬件周期 baseline；
- single-Tile sequential 是 NMC 内部的无网络参考；
- 如果要声称“相比集中式计算”，还需要定义一个具有明确计算资源、内存带宽和数据移动成本的 centralized baseline。

主指标应是：

```
total cycles
kernel cycles
speedup
throughput
```

辅助指标再报告：

```
flit-hops
FIFO stalls
Bank conflicts
MAC utilization
Root waiting
```

最终的核心结论应该来自 total-cycle geometric mean，而不是只看 flit-hop 或局部通信量。

### 第二层：NMC 内部消融实验

这是解释 NMC 为什么表现不同的实验。

包括：

```
compact vs spread
1 Root vs 2 Root vs 4 Root
central vs tree vs grouped-tree
different FIFO depths
different Root service capacity
different Bank organizations
```

这一层不负责证明 NMC 相比集中式 baseline 有优势，而是解释：

- NMC 的瓶颈在哪里；
- 为什么某些 workload 适合 ROW；
- 为什么某些 workload 适合 K；
- placement 是否造成热点；
- 多 Root 是否缓解归约瓶颈；
- Bank 资源是否改变最佳映射。

### 第三层：Mapper 研究实验

这是证明 proposed mapper 是否有价值的实验。

比较：

```
fixed compact
fixed spread
compute-balanced
minimum-hop
static communication-aware mapper
Bank-aware mapper
reduction-aware mapper
finite-catalogue Oracle
```

这一层才回答：

> 在同一个 NMC 硬件预算下，通信感知/资源感知 Mapper 是否优于简单启发式？

它不是回答 NMC 是否优于集中式计算，而是回答：

> 在已经选择 NMC 架构之后，好的 Mapper 是否优于简单放置策略？
