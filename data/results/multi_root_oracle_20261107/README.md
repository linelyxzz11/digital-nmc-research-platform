# 多 Root 放置 Mapper：第三层研究证据整合

本批材料对应《项目主线》的第三层 Mapper 研究，不能标注为独立的 Bank 收益实验：它没有扫描 Bank 组织/端口预算；也不能证明 NMC 相对集中计算的架构收益。

## 数据核对结果

72 个比较组、2160 个候选；命中有限目录 Oracle 38/72（52.78%）；平均 regret 5.44%，最坏 28.45%。相对固定 compact 几何平均加速 1.052×，相对 spread 1.132×。

本次重新核对 CSV 的候选数、组内最小周期、选中候选与基线周期、regret 和加速比公式。候选的 golden_ok 全为 True，这是交付数据记录，**不代表本次重新执行了数值仿真**。精确重算汇总在 audit.json。

## 可支持与不可支持的结论

- 支持：有限候选目录内，通信感知放置总体优于固定放置，但仍存在误选；Oracle 是目录内最优，不是全空间最优。
- 每组固定 Root 数量、分块网格和资源条件，再选择 Worker/Root 位置；不是联合自动选择 Root 数量、切分和归约方式。
- 只覆盖 central reduction；没有完成 central/tree/grouped-tree 的统一搜索。
- 静态排序没有以完整 Bank 冲突/Root 服务时序为评分输入。要证明 Bank-aware 的独立收益，需要固定其他因素，对 Bank 配置与评分机制做消融。
- 原包未附约 76 MB 的详细 results.json；因此保留证据边界，不能声称完整 Trace 已复核。
